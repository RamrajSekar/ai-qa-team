## Existing assets and migration implications

Stories and acceptance criteria remain the primary test-specification inputs; scenarios can seed test drafts. Recording-derived approved knowledge supplies context and conflict checks, not automatic new expectations. Existing records remain source material until reviewed under the new version/approval contract. Their boolean approval does not constitute approval of a new immutable knowledge/test version. Preserve original IDs, authors and provenance, keep observed versus expected semantics, require reviewer confirmation of explicit assertions. Locator/code-bearing cases must stay legacy mode or be converted through a reviewable mapping; do not execute their code in the visual runtime. Existing datasets are arbitrary values, not validated rule-constrained inputs.

Prompt versions, provider abstraction, encrypted secret interface, membership helpers, Mongo history, UI components and flag provider are useful implementation patterns. Reuse these deliberately without treating their domain schemas as sufficient for knowledge governance. Static registry records may be replaced on same-commit rescan (`repository_routes.py:67`); they cannot serve unchanged as immutable approved artifacts. Publication must be atomic before relying on snapshots for runs.

Migration should be additive and opt-in: new typed specifications/knowledge/media artifacts and explicit runner identifiers; preserve legacy testcases/stories/scenarios/recordings/executions/discovered_tests. New result envelopes retain raw runner result and new verdict separately. Existing runs lacking assertion evidence remain legacy/unverified, never automatically pass in the new vocabulary. Preserve user/project IDs, ownership and billing owner; do not infer missing membership from unrelated emails. Backfill only unambiguous legacy ownership with dry-run reports; current lazy creator membership is a reuse point, not a blanket tenant migration.

Secrets require separately scoped migration of environments, queue entries, execution snapshots and logs: inventory references without printing values, encrypt/store runtime credentials, replace payloads with scoped refs, rotate exposed credentials as appropriate, handle old queued jobs explicitly with owners, and validate historical display redaction. A new safe runner must not consume old payloads by accident. Do not erase customer history as a shortcut. Retention/deletion must reconcile evidence references and backups; approved immutability does not mean indefinite storage of personal data.

## Security and reliability priorities

1. **Isolation holes are present even with execution disabled.** `testcase_routes.py:242` fetches by testcase ID without project/creator restriction; list at :260 builds optional filters without authorization scope. Authentication is not authorization. New paths use membership, legacy paths are inconsistent. Audit all object references including uploads, vectors, jobs and artifacts before own-app pilot. This is a static finding, not an exploit test.
2. **Secret handling is inconsistent.** AI BYOK encrypted references are good reuse; environment credentials/API snapshots/Redis are not. `subscription_routes.py:34` prints cookies/user object; recorder prints captured records. Redact at source and prevent future secret-bearing observations/prompts. Never treat HTTPS or encrypted-at-rest Mongo as sufficient.
3. **Approval/verdict correctness is missing.** Mutable approved scenarios, editable testcases, no pinned test/knowledge versions, and pass-on-manual/empty assertions cannot meet reliable outcomes. Explicit assertion evaluation and immutable snapshots are critical path.
4. **Queue correctness and charging need redesign at the boundary.** Current newest-first destructive list pop has no durable lease/ack/reconciliation/cancel. Mongo write then Redis push is not atomic; both lost dispatch and duplicate charge are possible. Reuse infrastructure, add safe protocol.
5. **Browser/network and media isolation are new.** No robust origin/redirect/subresource/metadata controls found in StepEngine; relative/full URL acceptance at :70 is not SSRF protection. Source/frames/pages can carry prompt injection. Enforce policy outside model reasoning, use isolated profiles and restricted processors.
6. **Commercial configuration is not billing enforcement.** Own-plan upgrade has no payment check; AI credits have better atomic accounting than old execution counters. Evaluation refund semantics and dollar ceilings need distinct accounting.
7. **Dependency/deployment drift.** No reproducible new runner environment, images, license inventory, cloud manifests or browser upgrade/rollback gate. Existing local binaries/packages do not certify a deployable configuration.
